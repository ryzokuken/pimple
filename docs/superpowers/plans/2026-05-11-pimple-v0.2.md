# pimple v0.2 Implementation Plan

> Companion to `docs/superpowers/specs/2026-05-11-pimple-v0.2.md`. Each task lands as its own commit, follows red→green TDD, and leaves the workspace fully green before moving on.

**Goal**: deliver edit + delete (with three-way recurring semantics), month view, first-run picker, AppConfig persistence, configurable week start, window-geometry persistence, and concurrent-write detection.

**TDD discipline**: write the failing test first, run `just tdd-core <name>` (or `just tf <name>`) to confirm red, implement the minimum to go green, run `just check` before commit.

## Task 1 — AppConfig persistence

**Why first**: unblocks tasks 2 and 3, gives every later task a place to persist user state.

**Files**:
- `crates/pimple-core/src/config_store.rs` (new)
- `crates/pimple-core/src/config.rs` (extend `AppConfig`)
- `crates/pimple-core/src/error.rs` (already has `Io`)
- `crates/pimple-tauri/src/commands.rs` (new commands `get_config`, `set_config`)
- `crates/pimple-core/Cargo.toml` (add `dirs`, `toml`)

**Steps**:

- [ ] **1.1 Red — write `config_store_round_trip` test in `crates/pimple-core/tests/config_store.rs`**. Uses a `tempdir` and `XDG_CONFIG_HOME` override (via env var) to control path resolution. Writes a populated AppConfig, reads it back, asserts equal.
- [ ] **1.2 Green — implement `config_store::load(config_dir: &Path)` and `save(&AppConfig, config_dir: &Path)`**. TOML serde, atomic temp-file + rename. The path-resolution helper lives in `pimple-tauri` (since `dirs` is platform-aware); `pimple-core` accepts an explicit path so tests don't depend on env state.
- [ ] **1.3 Extend `AppConfig`**: `vdir_root: Option<PathBuf>`, add `window_geometry: Option<WindowGeometry>`. Update `ts-rs` exports.
- [ ] **1.4 IPC commands**: `get_config()` and `set_config(AppConfig)` in `pimple-tauri::commands`. Integration test: set, get, assert equal.
- [ ] **1.5 Commit**: `core: add XDG-backed AppConfig persistence`.

## Task 4 — raw_ics-patch core

This is the load-bearing piece for tasks 5–6. Until it's solid, edit/delete risks dropping VALARM/X-vendor properties.

**Files**:
- `crates/pimple-core/src/ical/patch.rs` (new)
- `crates/pimple-core/tests/round_trip.rs` (new)

**Steps**:

- [ ] **4.1 Red — `round_trip_preserves_unknowns` property test**. For every fixture in `tests/fixtures/ics/`, parse → apply identity `IcsMutation` → assert byte-equal modulo DTSTAMP. Will fail because `patch.rs` doesn't exist.
- [ ] **4.2 Red — fixture `with_valarm.ics` and `with_x_apple_color.ics`** — events including a VALARM block and an `X-APPLE-CALENDAR-COLOR` property. Round-trip test asserts these survive a `SetSummary("Edited")` mutation.
- [ ] **4.3 Green — implement `IcsMutation` enum and `patch_ics`**. Approach: line-by-line walk with a property-aware parser. For non-mutated properties, copy bytes through unchanged. For mutated, re-fold per RFC 5545 §3.1.
- [ ] **4.4 Commit**: `core: add raw_ics patch path with round-trip preservation`.
